# 字幕手册：每一刀都有一行字

用户的原话：**"最好把每一页的中文字幕都写上去，否则差点意思。"**

这句话同时否掉了两种常见做法：

- **只给"重点句"打字幕**。留白的地方观众在等下一张卡片，画面本身又什么都没说——这是
  最难受的一种半成品。
- **把歌词做成 PPT，一句一句打出来**。观众在等文字打完，画面退成背景板。
  见 SKILL.md「做 MV：一句一景，不要『一句一句放』」。

正确形态是：**每一刀都有一行字，但永远只有一行，且不用任何 PPT 装置**
（没有 kicker、没有页码、没有进度条）。字是画面的注脚，不是画面的主体。

## 一、切点跟着人声走

有了"每刀都有字幕"，切点就不能再由"每 2 小节换一张"决定——那样字幕会和人声错开：
字先出来，人还没唱；或者唱完了字才换。切点必须来自**这一句是什么时候唱的**。

所以镜头表里写的是 `t`（秒），不是小节号：

```js
{ t: 104.27, zh: '约定要好好珍惜', m: 'wrap', p: 'stand', f: 1, s: 0.40, x: 0.64, g: 1 }
```

然后由脚本把它吸到最近的**八分音符**上：

```js
const Q = F.grid.periodSec / 2;                    // 八分音符
const snapped = (t) => Math.max(0, Math.round((t - F.grid.beat0) / Q) * Q);
```

为什么不吸到小节？吸到小节会把切点推离那个字最多三分之一秒——在歌词片里，
这点抖动正好是最容易被看出来的那种。不吸则完全丢掉网格，测 BPM 就白测了。
八分音符是这两者之间的唯一平衡点。

### 时间码从哪来，以及那个 9.59 秒的坑

优先级：官方 MV 字幕时间码（有就是地面真值）> 正规 LRC > 自己听。

**但官方 MV 不等于单曲。** 实测（lulu.）：官方 MV 的中文字幕比单曲整轨晚 **9.59 秒**
（MV 字幕第一句 11.09s，单曲在 1.0s 处就已经 −16 dB 了）。你渲染的是哪一个，
就要用哪一个的时间码。核对办法：看波形起音点，或者拿 `features.json` 的 onsets
做一次 offset 扫描；不要凭"官方的肯定没错"直接套。

### 没有人在唱的时候怎么办

副歌的 scat、哼唱段、纯器乐尾奏——**仍然要有字**，否则就是缺口：

| 段落 | 做法 | 例 |
|---|---|---|
| scat / 啦噜噜 | 按原曲音节写，**不用引号、不加标点** | `哒—咚—哒　啊噜噜噜噜噜噜` |
| 哼唱（鼻歌） | 写歌里那几个音 | `只好藏进哼唱里　啦啦啦` |
| 尾奏 | **留住最后一句**，一直留到画面淡出 | `还温热地留着` × 4 刀 |

尾奏留字不是偷懒：那句话是片子结束的那个词，让它留在银幕上，比留下 19 秒无字的
风景更诚实。

## 二、字幕不许压在人身上

这是"加了主角之后最先暴露的问题"。字幕在下方（`head` 槽，0.735H），她的脚底在
0.88–0.92H，她一站过去，字就压在她腿上。

老办法是"让她退到 0.28 或 0.72，双人镜头把字挪到上方"——能解决，但有两个毛病：
20 个有字的镜头构图会长得一模一样；双人镜头一挪到上方，就和下方的动作脱开了。

**新办法：算出来。** 字幕盒由她的位置、姿态和朝向反推，写在 `lyric` 块的 `dx`/`w` 上，
（`stage` 版式的 `head` 槽是 `x 0.06, w 0.88`，`dx`/`w` 是占这个槽的比例）：

```js
const POSE_HW = { stand: 0.20, walk: 0.20, lookup: 0.20, crouch: 0.24,
                  kneel: 0.27, reach: 0.27, sit: 0.37 };
const FIG_HW = (s, pose, W = 1920, H = 1080) => (POSE_HW[pose] ?? 0.20) * s * H / W;

function captionBox(sh, W = 1920, H = 1080) {
  const hw = FIG_HW(sh.s, sh.p, W, H);
  const bareR = sh.x + hw, bareL = sh.x - hw;
  const side = (0.94 - (bareR + 0.026)) >= ((bareL - 0.026) - 0.06) ? 'right' : 'left';
  const gs = sh.g ? (side === 'right' ? -1 : 1) : 0;     // 他站在哪边
  const right = bareR + (gs > 0 ? 0.145 : 0);
  const left  = bareL + (gs < 0 ? -0.145 : 0);
  if (side === 'right') {
    const x0 = Math.max(0.06, right + 0.026);
    return { side, dx: +((x0 - 0.06) / 0.88).toFixed(4), w: +Math.min(1, (0.94 - x0) / 0.88).toFixed(4) };
  }
  const x1 = Math.min(0.94, left - 0.026);
  return { side, dx: 0, w: +Math.min(1, (x1 - 0.06) / 0.88).toFixed(4) };
}
```

三条规则藏在里面：

1. **先只看她一个人定边**，选剩下空间大的那一边。
2. **第二个人站到字幕的反面**（`gs`）。双人镜头如果把字夹在两具身体中间，
   那行字会窄到装不下一句话——这是原来 7 个镜头字幕盒窄于 0.40 的原因。
3. **字宽按姿态算，不按 `s` 算。**

## 三、为什么宽度要按姿态算

`figure.js` 里斗篷下摆画在 `hw * 0.185`，而 `hw = h / BONES[pose].H`：

```js
const BONES = { stand: { H: 1.00, ... }, crouch: { H: 0.80, ... },
                kneel:  { H: 0.72, ... }, sit:   { H: 0.56, ... } };
```

**坐姿的 `BONES.H` 是 0.56**——也就是说一个坐着的人，实际占的画面宽度是 `s` 这个数字
暗示的近 **1.8 倍**。`sit` 伸出去的腿、`reach` 伸出去的手臂还要更宽。按 `s` 估宽度，
字幕必然印在膝盖上。所以每个姿态一个半宽系数（单位：她的身高）：

| 姿态 | `POSE_HW` | 说明 |
|---|---|---|
| `stand` `walk` `lookup` | 0.20 | 站姿，肩宽 |
| `crouch` | 0.24 | 蹲下，胯张开了 |
| `kneel` | 0.27 | 跪，膝盖向前 |
| `reach` | 0.27 | 手臂伸出体外 |
| `sit` | **0.37** | 腿伸出去，最宽 |

## 四、字号、容量与换行

`lyric` 块给 `scale: 1.26`（约 54 px @1920）。一条中文字宽约等于字号，
所以**字幕盒的像素宽 ÷ 字号 = 能放几个全角字**。

算一遍就够：`build_deck.mjs` 末尾会打出所有窄于 **0.40** 画宽的盒子（提醒线），
`deck_smoke.mjs` 另有 **0.34** 的硬报警线。
窄于 0.40（≈717 px ≈ 13 个全角字）的行，必然换行；换行不是灾难，
但两行字会吃掉画面下部一大块，所以最好在镜头表里就把那句改短。

scat 那两句原来写作 `哒—咚—哒　啊—噜噜噜噜噜噜`（14 字），
正好超过 13 字的容量 → 改成 `哒—咚—哒　啊噜噜噜噜噜噜`（13 字）。

**用全角空格 `　` 分句**，不要用逗号。逗号在画面上是噪声。

## 五、暗色主题上的可读性

字幕底下 `R.lyric` 会铺一层 `pal.bg` 的渐变带 + 一条强调线，所以不会被母题的亮部吃掉。
但要注意两件事：

- **浅色主题（`warm-paper`）判对比度不能按"比背景亮"**。浅色墨压在浅底上，
  只能按分位数区间（p95−p05）判断，见 `references/qa-and-delivery.md`。
- **别靠"把字再往下压"来避人**。她的脚底就在那儿。

## 六、验收

```bash
node tools/build_deck.mjs     # 末尾那五行就是验收单
node scripts/deck_smoke.mjs . # 含"字幕盒过窄"与"hit 比例"检查
node scripts/qa_pixels.mjs .  # 每页是否真的有内容
```

要盯的五个数字：

| 指标 | 合格线 |
|---|---|
| `subtitles` | **等于镜头数**，少一个都是缺口 |
| `caption boxes under 0.40` | `none` |
| `average` | 3.0–4.0s（270s 的歌 70–85 刀） |
| `shortest` | ≥ 1.4s，短于 QA 的 settle 窗口会量成空页 |
| `adjacent / one-apart repeats` | 都是 `none` |

肉眼看仍然只能靠格子图：

```bash
node export/export.mjs --sheet out/sheet.png --cols 15 --width 960 --height 540 --times <每刀中点>
```

一排 15 格扫过去：**字压在腿上、字被夹在两个人中间、字换行、字没了**——都是一眼的事。
（本环境的模型读不了 PNG，所以这些只能由人来看；`tools/build_deck.mjs` 的算术检查
是给人减负的，不是替代。）
