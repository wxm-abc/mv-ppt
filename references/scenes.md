# `src/scenes.js` — 母题（motif）手册

`deck.js` 画的是**图解**（bars、steps、compare、cycle）。MV 需要的是**画面**：一个不把话说破、
但能承载那句歌词的意象。`scenes.js` 里每个函数就是一个这样的意象，用矢量画出来，由拍子驱动动画。

## 契约

```js
S.motif = (ctx, b, r, H, pal, k, env) => { ...; return r.h; }
```

| 参数 | 含义 |
|---|---|
| `ctx` | 画布上下文 |
| `b` | deck.json 里那个 `scene` 块的字段，`b.motif` 选画哪个。其余字段原样传进来（`n` `pts` `petals`…） |
| `r` | 画区 `{x, y, w, h}`。`layout:"stage"` 时 `r` 就是整幅画面 |
| `H` | 画面高。**一切尺寸都按 H 的比例写**，960×540 与 1920×1080 构图才会一致 |
| `pal` | 主题色板，见下 |
| `k` | 入场进度 0..1（`easeOut` 过的） |
| `env` | `{u: 翻页以来的拍数, p: 本页进度, beat, flare, index}`。**动画全靠 `u`** |

两条硬性要求：

1. **纯函数**。没有 wall clock、没有 `Math.random()`、没有跨帧状态。否则导出器无法单独渲染第 6000 帧。
   需要随机感就用 `hash(i)`（整数进，0..1 出）。
2. **画满**。`scene` 是满幅块，涂不满的画面会量成"空白页"（见下面的审片）。

## 色板角色

`engine.js` 把 `config.json` 的 PPT 色板映射成语义角色：

| 角色 | 该用在 |
|---|---|
| `pal.bg` | 页面底色 |
| `pal.plate` / `pal.raised` | 后景板、卡片、纸张。**必须与 `bg` 差 ≥19 亮度**，否则卡片只剩描边 |
| `pal.line` | **暗色主题**下的发丝线。⚠️ 浅色主题里它本身就是浅色，画结构会看不见 |
| `pal.sub` | ✅ **跨主题的结构线**：浅色主题是深色，暗色主题是浅色 |
| `pal.ink` | 主文字色。也是"提亮/压暗一层"的原料：暗色主题近白、浅色主题近黑 |
| `pal.mute` | 最弱的注释 |
| `pal.accent` / `accentHot` / `accentDim` | 主色 |
| `pal.glow` | **bloom**。⚠️ 只为暗色页面调的 |
| `pal.err` | 错误色 |

## 浅色主题的四个坑（都踩过）

这四条是同一件事的四种表现：**暗色主题的写法搬到浅色主题上会整片消失**。

### 1. 结构线用 `pal.sub`，不要用 `pal.line`

`warm-paper` 的 `line` 是 `#c9bda6`，底色 `#f2ece0`——差几步就看不见。原本用 `line` 画的
风纹、地纹、环、线全部消失，那一页量出来 ink 8.8%、动态范围 38，肉眼就是一张空纸。

### 2. 环境光要用"按底色亮度自适应"的颜色

```js
const ambient = (pal) => (lum(pal.bg) > 0.6 ? mixHex(pal.glow, pal.accent, 0.5) : pal.glow);
```

`warm-paper` 的 `glow` 是 `#ffd9a8`，**比纸还深**。一盏用 `glow` 点亮的灯画在浅色主题上
量出来 ink 5.3%、范围 30——等于没点。浅色主题上的光必须往该主题的 accent 偏。
`lum()` 就是判底色亮度的，别用"我猜这是浅色主题"。

### 3. 要让**表面**浮起来，用 `ink` 叠一层

```js
ctx.fillStyle = hexA(pal.raised, 0.94); ctx.fill();
ctx.fillStyle = hexA(pal.ink, 0.11);    ctx.fill();   // 暗色主题提亮，浅色主题压暗
```

固定一个浅色只在一个主题上成立。

### 4. 要"比纸还亮"的东西（门里透出的光）得混白

```js
const hot = mixHex(pal.glow, '#ffffff', 0.45);
```

`glow` 在浅色主题上仍然比 `bg` 深，所以一扇只用 `glow` 填的门看起来是**木门**。
混白之后才是光。注意 `hexA()` 只认 `#rrggbb`——`mixHex` 必须返回 hex，
返回 `rgb(...)` 会让 `hexA` 解析出 NaN，画出一整片黑（这个 bug 真发生过）。

## 母题与主角的关系（加人物之后才发现的）

**画面里有一个人之后，母题的尺度要重算。** 同一朵 `bloom`，没有人时是一团抽象的光；
有人站在里面时，它是一堵花做的墙——人物被吞掉了，只剩一颗头露在花瓣中间。

规则：**母题读到 `b.figure` 就要退成背景。**

```js
const hasFig = !!b.figure;
const sc = hasFig ? 0.58 : 1;                  // 尺度降一半
pg.addColorStop(0, hexA(pal.accentHot, hasFig ? 0.48 : 0.85));   // 对比也降一半
```

同样要检查的：任何"以画面中心为圆心、半径按 `r.w` 算"的图形。`r.w` 是**画面宽**，
所以 `r.w * 0.30` 的花瓣在 1920×1080 上是 576px 长——从 0.52H 的画面上方算起，
会直接顶出画框。

判据不是肉眼看，是量：有人物时图形区的 `ink%` 应该仍然 ≥ 20%，
但人物的**轮廓**要在像素里能分辨出来（把人物那一列单独裁出来量对比度）。

## 构图：不要满屏都是"中间一团光"

83 个镜头里最容易失控的是母题分布。审片时最容易看出来的问题不是错，是**重复**：

- 相邻两刀同一个母题 → 读成卡带
- 隔一刀又回来 → 还是重复
- 连续好几页都是"居中一团径向光" → 整支片子像同一张图换色

所以：母题按意象选，但**排完要数一遍重复**（`tools/build_deck.mjs` 末尾自动报）。
同一个母题最好在片子里承担同一个意思，回来的时候要隔得够远。

第一版 83 刀只用 18 个母题，平均一个用 **4.6 次**，看总览图就露馅了：缩略图里
很多格子是"米色背景 + 橙红渐变 + 黑色剪影"，几乎分不出哪格是哪格。改版做了两件事：

1. **母题补到 30 个**（平均 2.8 次）。补的时候不是随便加，是补**空间结构不同的**——
   原来 18 个里一大半是"以画面中心为圆心的一团光"，于是补了横向的（`cliff` `field`）、
   纵向的（`lanterns`）、强透视的（`corridor`）、对称的（`mirror`）、大圆形的（`moon`）。
2. **加了主角**。同一个地方、她在画面另一处做另一件事，就是另一个镜头——
   这是把 30 个母题变成 85 刀而不显重复的真正手段，见 `figure.md`。

构图也要换：不是每个母题都居中。`thorn` 的刺从右上进来、`door` 的门偏右、
`path` 的路通向 `0.30H` 的消失点、`cliff` 的崖石只占左边 0.30W。
全都居中就等于没构图。

第二批 6 个，全都是为了**换空间结构**：

| 母题 | 意象 | 结构 | 地面 `y` |
|---|---|---|---|
| `cliff` | 站在崖边 | 横向：左边崖石、右边云海 | 0.605（崖顶） |
| `field` | 草浪 | 横向纹理：210 根草分三层、同向倾 | 0.820 |
| `moon` | 最大的一个形体 | 大圆 + 水面光路 | 0.735 |
| `mirror` | 水面里的自己 | 对称：水线切开画面 | 0.660（水线） |
| `corridor` | 走过一条长廊 | 强一点透视：7 开间向消失点收 | 0.880 |
| `lanterns` | 升起的灯 | 纵向：26 盏灯只往上走 | 0.875 |

`mirror` 的特殊之处：**水面下的倒影是人物自己画的**（`figure.mirror` ＝ 水线位置），
不是另画一个影子。另画一个的话，她一走，倒影就和她错开了。
`cliff` 的崖石只在 `x ∈ [0, 0.30]`，所以人物 `x` 必须 < 0.26，否则站在空气里。

`scene` 块写法：

```json
{ "type": "scene", "motif": "ember", "at": 0, "dur": 0.45,
  "fill": 1, "slot": "main", "from": "none", "hit": true }
```

⚠️ **`from` 必须显式给 `"none"`**。默认的 `up` 会把满幅画面往上推 4.5%H，
边缘露出一条底色——满幅的东西不能滑动。

## 加一个新母题

1. 在 `S` 上写函数，遵守上面两条硬性要求。
2. 起手用 `wash(ctx, r, pal, e)` 铺一层斜向渐变，别留两块纯色。
3. 主结构用 `pal.sub` 描线，实体用 `pal.raised` 再叠 `pal.ink` 提亮。
4. 光用 `glow(ctx, x, y, r0, ambient(pal), a)`。发光体的核用 `pal.accentHot`。
5. 需要"进入"的动作用 `easeOut(clamp01(u * 速度 - 序号 * 间隔)) * e`，
   `u` 是拍数。让元素**依次**出现——这是从 PPT 缓入继承来的、最便宜的高级感。
6. 每个可数元素配一个 `hash(i)` 的微扰，否则会像批量复制的图钉。
7. 跑 `deck_smoke.mjs`（NaN 几何、mock 缺 API）和 `qa_pixels.mjs`（空白页）。

## 验证

```bash
node scripts/deck_smoke.mjs .        # 无浏览器，抓崩溃 / NaN / 空页
node scripts/qa_pixels.mjs .         # 出像素，抓「没崩溃但画面是空的」
```

`qa_pixels.mjs` 的判读：

- `ink%`：内容密度。文字页 3–4% 正常，**母题页应该在 25–76%**。
- `lower%`：图形区覆盖。低于 2% 说明图形区没画东西。
- `edge%`：边缘密度。**母题页天然低**（大片渐变），所以它只在 `ink` 也低时才判"空且平"。
- `rng`：成片动态范围。低于 20 就是一片平。

要肉眼看，用 `export/export.mjs --sheet`。一次看全片的格子图（`--cols 9 --width 426`）
比逐帧看快得多，重复构图一眼就能看出来。
