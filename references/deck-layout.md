# 版式母版详解（src/deck.js）

`data/deck.json` 说「这一页有什么」。`src/deck.js` 说「这些东西长什么样、放在哪」。
它是幻灯片母版 + 版式库，全部跑在 canvas 2D 上，因此每一页都能被逐帧渲染。

读这份文档的时机：要加一种新的图形元件、要改网格或字号、页面出现了溢出或错位。

---

## 1. 坐标系：一切都是比例

没有 1920 这个数字出现在绘制逻辑里（只有 stage.js 的内部画布是固定的 1920×1080）。
`deck.js` 里所有位置与尺寸都是 W / H 的比例，所以同一份 deck 在 960×540 预览、
1280×720 contact sheet、1920×1080 导出下**构图完全一致**——这是逐帧渲染器能省掉
「响应式」这件事的原因。

```js
safe(W, H)              // 安全框：左右留白 7.8%，上下留白 10.5%
col(box, i, n)          // box 内第 i 栏起、跨 n 栏的像素矩形
part(box, x, y, w, h)   // box 内按比例切一块（全部参数 0..1）
```

**安全框是硬的。** 除了刻意出血的图形，任何内容都不许出框。电视与短视频平台都会在边缘
裁掉一圈；7.8% 是这个骨架替你留出的余量。

网格参数在 `GRID`：

```js
{ cols: 12, gutter: 0.016, mx: 0.078, my: 0.105 }
```

想改留白就改 `mx/my`；注意 `stage.js` 的背景网格线是照着同一组数画出来的，
改了这里也要改那里，否则页面会跟背景网格错位一格，很显眼。

## 2. 字号：六级，比例制

```js
SCALE = { kicker: 0.028, title: 0.082, sub: 0.040, body: 0.030, caption: 0.022, stat: 0.155 }
```

在 1080p 下分别是 30 / 89 / 43 / 32 / 24 / 167 px。

三个字型角色（`config.json -> fonts`），各有分工：

| 角色 | 字体 | 用在哪 |
|---|---|---|
| `mono` | JetBrains Mono | kicker、数字、footnote、页码——所有「标签」 |
| `sans` | Inter | 标题、正文、卡片——所有「界面」 |
| `serif` | Source Serif 4 | 引言——「说话的声音」 |

**层级规则：一页至少三档字号在场。** 只有标题和正文两档，页面会读成海报；
四档以上且没有明显主次，会读成仪表盘。

### 中文字号陷阱（实测）

内置字体是拉丁字库，中文靠 `fonts.cjk` 回退。回退链缺失时浏览器会挑一个字体，
而**笔画多的字在小字号会糊成一团**：实测 30px 下 `翻`（18 画）、`暖`（13 画）会变成黑方块，
`风`（4 画）、`远`（7 画）正常。

所以：

- 每个品牌角色后面都接 `fonts.cjk` 回退链（`initDeck()` 已经做了，不要绕过它）。
- **kicker 里放中文要谨慎**：它是 30px 的标签位，放 `CHAPTER 01` 或 `01 / 05` 最稳；
  中文关键词交给 `title`（89px）。
- 如果非得在小字号放中文，把 `SCALE.kicker` 提到 0.034 以上，并改用 `sans` 角色。

## 3. 版式与插槽

版式把安全框切成具名插槽。`LAYOUTS` 里的数字都是**安全框的比例**：

```js
const LAYOUTS = {
  cover:    { head: [0, 0.14, 1, 0.50], main: [0, 0.66, 1, 0.22], foot: [0, 0.92, 1, 0.08] },
  headline: { head: [0, 0.00, 1, 0.30], main: [0, 0.34, 1, 0.58], foot: [0, 0.94, 1, 0.06] },
  split:    { head: [0, 0.00, 1, 0.24], main: [0, 0.28, 0.47, 0.66], side: [0.53, 0.28, 0.47, 0.66], foot: [0, 0.96, 1, 0.04] },
  bullets:  { head: [0, 0.02, 0.44, 0.88], main: [0.48, 0.06, 0.52, 0.82], foot: [0, 0.94, 1, 0.06] },
  cards:    { head: [0, 0.00, 1, 0.26], main: [0, 0.30, 1, 0.62], foot: [0, 0.96, 1, 0.04] },
  chart:    { head: [0, 0.00, 1, 0.26], main: [0, 0.30, 1, 0.60], foot: [0, 0.94, 1, 0.06] },
  compare:  { head: [0, 0.00, 1, 0.26], main: [0, 0.30, 1, 0.60], foot: [0, 0.94, 1, 0.06] },
  quote:    { head: [0.06, 0.08, 0.88, 0.18], main: [0.06, 0.32, 0.88, 0.48], foot: [0, 0.92, 1, 0.08] },
  full:     { head: [0, 0.00, 1, 0.20], main: [0, 0.22, 1, 0.72], foot: [0, 0.96, 1, 0.04] },
};
```

### 块怎么归位

1. 块写了 `slot` → 强制去那个插槽（插槽不存在就丢弃，`side` 只在 `split` 里有）。
2. 没写 → 按类型猜：`kicker/title/sub` 进 `head`，`pagenum/progress/footnote` 进 `foot`，
   其余进 `main`。

同一插槽里的块**自上而下栈式排布**，间隔 `b.gap`（默认 `H * 0.018`）。
整个插槽的内容可以按 `slide.valign: "middle"` 垂直居中——短内容的页面（封面、收尾引言）
几乎都需要它，否则内容会全部挤在插槽顶部，下面留一大片空。

### 加一个新版式

往 `LAYOUTS` 加一行即可。两个坑：

- **head 的高度要放得下标题。** 89px 的标题两行就是 206px，加上 kicker 与间距约 260px，
  而安全框高度是 844px，所以 head 至少 0.30。给 0.19 会让标题压到 main 上，
  而且不会报错——`deck_smoke.mjs` 也查不出这个，只能靠 contact sheet。
- **别让 head 和 main 重叠**（`quote` 早期版本两个插槽是同一个矩形，正文就叠在标题上）。

## 4. 缓入：stagger 与 enterK

这是「版面感」的算法本体，只有两个函数。

```js
stagger(blocks, enterBeats)   // 给每个块算出 at（从翻页起算的拍数）与 dur
enterK(block, u)              // u = 该页已经过去的拍数 -> 0..1 的入场进度
```

`stagger` 的规则：

- 显式写了 `at` 就用它；否则第 i 个块落在 `i * stride`。
- 单个块时长 `d = min(1.4, max(0.6, enterBeats / n))`——块多则每个更快。
- 步长 `stride = max(d * 0.55, (enterBeats - d) / (n - 1))`——保证**最后一个块在窗口内落完**，
  同时相邻块至少重叠 45%（不重叠就成了「依次闪现」，PPT 的缓入是叠着走的）。

`enterK` 做两件事：先算入场进度，再支持退场（`outAt` / `outDur`）。
缓动用 `easeOut`——入场必须减速落地，线性入场会读成「机械」。

`entrance()` 把进度变成变换，由块的 `from` 决定：

| from | 变换 | 适合 |
|---|---|---|
| `up`（默认） | 上移 `0.045H` | 正文、列表 |
| `left` / `right` | 横移 `0.06H` | 与旁边元素有方向关系时 |
| `scale` | 0.9 → 1.0 | 数字、徽章 |
| `none` | 只淡入 | 大块图形、背景元件 |

**不要所有块都用 `up`。** 一个页面上两种方向就够了，再多就变成「到处都是动」。
方向应当有含义：标题从上、要点从左、数字从缩放。

## 5. 图形元件

它们是「每页一图」那条规则的弹药。每个元件都吃一个 `k`（入场进度），所以图形自己会长出来，
不用另写动画。

| 类型 | 必填字段 | 可选字段 | 长什么样 |
|---|---|---|---|
| `kicker` | `text` | `bar`（前面的短横）, `size` | 拉开字距的小标签 |
| `title` | `text` | `align`, `valign` | 大标题，支持强调标记 |
| `sub` | `text` | `align` | 副标题 |
| `body` | `text` | `lh`, `align` | 正文段落 |
| `quote` | `text` | `by`, `scale`, `align` | 引言，衬线体 + 大引号 |
| `bullets` | `items: [string \| {text, icon}]` | `icon`, `numbered`, `size`, `lh`, `reveal` | 逐条入场的要点列表 |
| `bars` | `items: [{label, value}]` | `max`, `unit`, `labelW`, `fmt` | 横向条形图，条自己长出来 |
| `timeline` | `items: [{label, sub}]` | `hot`, `axis` | 时间轴，节点逐个亮 |
| `steps` | `items: [string \| {text}]` | — | 带序号的流程块 + 箭头 |
| `cards` | `items: [{icon, title, text}]` | `cols` | 卡片网格，逐张浮起 |
| `compare` | `left`, `right`: `{tag, title, items[]}` | `hot`(0/1) | 左右对比，一侧高亮 |
| `cycle` | `items: [string]` | `center` | 环形图，弧线走一圈 |
| `stat` | `value` 或 `count` | `unit`, `delta`, `label`, `scale`, `decimals` | 大数字 + 变化量 + 注解 |
| `badges` | `items: [string]` | `scale`, `rows` | 药丸形标签排 |
| `rule` | — | `w`, `h` | 渐变强调线（`k` 让它横向画出） |
| `pagenum` | — | — | 页码 + 进度点 |
| `progress` | — | — | 顶部/底部细进度条 |
| `footnote` | `text` | — | 等宽小字注脚 |
| `spacer` | — | `h` | 占位空隙 |

`stat` 的 `count` 会随 `k` 从 0 数到目标值——**数字自己数上去**是 PPT 里最便宜的高级感。
用 `count: 12, decimals: 0` 得到「12」，`value: "3.2×"` 得到不动的字符串。

图标名（`glyph` 用的路径图标，无外部文件）：
`bolt check shield arrow star gear cloud lock chart eye`。

### 加一个新块类型

三步，都在 `deck.js` 里：

1. 在 `R` 上写渲染函数：`R.你的类型 = (ctx, b, r, H, pal, k, env) => { …; return 用掉的高度 }`。
   `r` 是把你的块包起来的目标矩形，`pal` 是主题色，`env` 有 `{u, p, index, total, flare}`。
2. 在 `measure()` 的 `switch` 里给出同一高度。**这两处必须一致**，否则插槽的居中会错位。
3. 完事。`BLOCK_TYPES` 自动带上它，`deck_smoke.mjs` 与 `deck_lint` 会认。

高度算不准时，用 `textHeight(ctx, text, rect, H, {step, lh, weight})` 先量再画；
所有文字元件都是这么写的。

## 6. 强调标记

PPT 里「加粗 / 下划线 / 文字色 / 文字底」对应四个标记，可以写在**任何**文字字段里：

```
[[强调色 + 加粗]]      {{反白底框（强调底色 + 背景色字）}}
__下划线（强调色）__   **更重的字重**
```

实现分四步：`parseRich` 切标记 → `tokenize` 切成可换行的最小单位（CJK 按字，拉丁按词，
每个 token 记住自己的标记）→ `wrapTokens` 贪心折行 → `drawLines` 逐个 token 画，
遇到 `box` 先铺底再反白。

**折行是标记安全的**：`[[变远]]` 中间被折断时，两半都还是强调色。
如果自己写新元件，不要用 `ctx.fillText(整段文字)`，那会丢掉标记；用
`textHeight` + `drawLines` 这一对。

一行里强调不要超过两处。四处强调等于没有强调。

## 7. 常见排版事故

| 症状 | 病因 | 处理 |
|---|---|---|
| 某页一片空白，控制台没报错 | 某个绘制参数是 NaN（漏了比例、除了 0） | 跑 `deck_smoke.mjs`，它会抓出 NaN |
| 正文压在标题上 | head 插槽太矮，或两个插槽重叠 | 调 `LAYOUTS` 的 head 高度 |
| 文字出框 | 块没有按插槽宽度折行，或标题太长 | `deck_smoke.mjs` 会警告超过 22 字的标题 |
| 元素全部挤在顶部 | 短内容没开 `valign: "middle"` | 页级加 `"valign": "middle"` |
| 中文变成黑方块 | 小字号 + 多笔画，或缺 CJK 回退 | 见 §2；kicker 放拉丁 |
| 卡片/对比里文字溢出一格 | `cols` 或 `rows` 与 `items` 数不匹配 | 卡片用 `cols` 控制列数，行数自动 |
| 图形元件「没长出来」 | 该元的 `k` 一直是 0 → 块的 `at` 大于页面时长 | 检查 `at` 与 `atBar` 的间隔（拍） |
