# 翻页与缓入怎么落在拍上

PPT 的版面感来自两件事：元素依次缓入，和干净利落的翻页。把它搬进 MV 时，这两件事
**都必须以拍为单位**，而不是毫秒。这份文档讲换算、选型，以及错位时的排查顺序。

读这份文档的时机：翻页位置拿不准、缓入看起来「一起来」或「拖太久」、转场感觉和音乐打架。

---

## 1. 三个时间尺度

| 尺度 | 单位 | 谁在用 | 典型值 |
|---|---|---|---|
| 页面 | 小节（`atBar`） | 翻页 | 2 小节 = 8 拍 |
| 入场窗口 | 拍（`enterBeats`） | 整页所有元素的缓入总长 | 3–6 拍 |
| 单元素 | 拍（`at` / `dur`） | 某一个块的落点 | `at: 0.5`, `dur: 1.4` |
| 转场 | 拍（内部算出的秒） | 页与页之间的切换 | 0.85 拍 |

秒只出现在两个地方：`features.json` 里的 `duration`，和导出时的 `--start/--end`。
**页面代码里不写秒。**

---

## 2. 翻页落点

```js
slideBounds(i)   // { a: bar(atBar_i), b: bar(atBar_{i+1}) }
```

- 页 0 从 0 开始（`atBar: 0` 常常正好是第一个歌词行）。
- 最后一页到 `features.duration` 结束。
- `deck_smoke.mjs` 会硬查「翻页是否落在小节线上」，并且会警告最后一页起点超过了歌的长度。

**先确认"一小节"到底是几拍。** 这一步错了，后面所有 `atBar` 都是错的。自相关给的是
**脉冲**，不是小节：实测 lulu. 给 175 BPM（`periodSec 0.3429`），于是"1 小节 = 4 拍 = 1.3714s"，
但真正的音乐小节是 8 个脉冲（2.7432s，87.5 BPM）——**175 是 87.5 的倍频**。
判别办法：把音频低通到 ≤110 Hz 再做起音自相关，看四分的周期。
那首歌的低频给出 quarter = 0.685s → 87.6 BPM，与"半速"吻合，所以 4 脉冲只是**半小节**。
同一首歌跑三次可能给出三个 BPM，用 `tempo_verify.cjs` 按相位集中度与漂移裁决
（175 的 R=0.119 / 漂移 0.097 拍；87.45 的 R=0.067 / 漂移 1.10 拍 → 87.45 是半速错觉）。

半小节照样可以当切分网格用（本片就是），**但要知道自己切在半小节上**，
不然"2 小节一刀"实际只有 1.37 秒，会比预期快一倍。

**页长怎么定。** 一页的时长应当由**歌词行**决定，不是由「一页看着差不多」决定：

- 歌词每 2 小节一行 → 页也每 2 小节翻（1 行 = 1 页）。
- 一行里有两个意思、需要两张图 → 一页一个意思，于是变成 1 小节翻一次。
- 副歌比主歌密 → 副歌用 2 小节，主歌用 4 小节。**页长跟着音乐密度变**，
  全曲等距翻页是「幻灯片自动播放」，不是 MV。

## 3. 入场窗口：把 PPT 的 1.5–2.5 秒换算成拍

`ppt-animation` 的经验值是「单页所有元素出现总计 1.5–2.5 秒」。换算：

```
enterBeats ≈ round(2.0 / spb)，spb = 60 / bpm
```

| BPM | spb (s) | 2.0 秒 ≈ | 建议 `enterBeats` |
|---|---|---|---|
| 70 | 0.857 | 2.3 拍 | 2–3 |
| 88 | 0.683 | 2.9 拍 | 3 |
| 100 | 0.600 | 3.3 拍 | 3 |
| 120 | 0.500 | 4.0 拍 | 4 |
| 134 | 0.447 | 4.5 拍 | 4–5 |
| 160 | 0.375 | 5.3 拍 | 5 |

**慢歌不代表缓入要长。** 上面这张表的分子（2 秒）是观感目标，它不随歌变；
慢歌的拍更长，所以换算出来的**拍数更少**。反过来把慢歌写成 `enterBeats: 8`，
入场就会拖到 6.8 秒——观众会以为卡住了。

**上限是页长的一半。** 一页只有 4 拍时，`enterBeats: 5` 会让元素还在入场就被翻走。
经验：`enterBeats ≤ 页拍数 / 2`。

## 4. 谁先谁后

`stagger()` 默认按块在数组里的顺序依次入场。顺序就是阅读顺序，所以**把数组写成你希望
观众看的顺序**：kicker → title → sub → 图形 → 页码。

需要精确控制时写显式的 `at`（单位拍）：

```jsonc
{ "type": "kicker", "text": "CHAPTER 02", "at": 0 },      // 翻页瞬间就有
{ "type": "title",  "text": "刺还在", "at": 0.5, "hit": true },  // 半拍后砸下来
{ "type": "sub",    "text": "…",     "at": 2.0 },          // 一拍半之后
{ "type": "bullets","at": 2.5 }                             // 最后进
```

三种典型节奏：

- **同步**：全部 `at: 0`，一起入场。适合 `cut` 翻页 + 硬切音乐，信息量小的页面。
- **依次**（默认）：错开半拍到一拍。适合绝大多数页面。
- **延迟重点**：前两三拍只有标题，图形在 2–3 拍后单独进来。适合「先给结论、再给证据」
  的页面——这也是让一页有第二段生命力的办法。

`bullets` 的 `items` 在进入时还会再按条错开（`reveal` 默认为真）。
**一层错开就够了**：整块 `bullets` 已经在窗口里错开，条目再错开一次是「错开的平方」，
在快歌里会碎掉。快歌请写 `"reveal": false`。

## 5. hit：一页的主角，和镜头的反应

每页标**一个** `hit: true` 的块。它是这一页真正要说的那一秒。引擎把它变成一个
0..1 的包络 `flare`：

```js
d = u - (at + dur * 0.6)          // 距离"落地"还有几拍
flare = d < 0 ? exp(d * 2.4)      // 接近时上升（攻击）
              : exp(-d * 1.7)     // 落地后衰减
```

`flare` 同时驱动后处理的五样东西——这就是「镜头对那一秒有反应」：

| 受控项 | 效果 |
|---|---|
| `fx.glow` | 泛光变强 |
| `fx.rays` | 从画面中心向外的光线 |
| `fx.streak` | 横向拉丝 |
| `fx.aberration` | 边缘色散（镜头「不舒服」） |
| `fx.bloomAll` | 连非高饱和区一起泛光 |

所以**不要标两个 hit**：两个尖峰等于没有尖峰（实现里取的是最大值，第二个会盖掉第一个）。
也不要每页都标在同一个位置——如果每页都是标题在砸，第三页之后观众就不看了。

## 6. 转场选型：按音乐在那个小节做什么决定

| 音乐上发生了什么 | `enter` | 理由 |
|---|---|---|
| 鼓/贝斯在拍点上砸下来 | `cut` | 硬切。硬切才是卡点，滑动不是 |
| 段落推进、加了一层乐器 | `push` | 有方向地推走，像往下读一页 |
| 两个并列的东西（前/后、你/我） | `wipe` | 横向揭示，带一条亮边 |
| 页的内容本身是「翻过去」 | `flip` | 绕书脊翻页，与语义同构 |
| 全曲最亮的一拍、副歌第一拍 | `flash` | 一帧白闪，由后处理加，被调色板染色 |
| 段落之间、需要喘一口 | `push` 或 `cut` | 不要用它做「变化」，用它做「呼吸」 |

转场时长由引擎算，不写死：

```js
transSec() = min(0.42, spb() * 0.85)   // 不到一拍，保证下一拍已经落定
```

**转场的总时长必须短于四分之一页**，否则页与页的内容会互相干扰。
一页 2 小节（8 拍）时，0.85 拍约占 10%，合适。

**不要给 push/flip 加径向模糊。** 被径向拉丝的是**一张平面**（不像实拍场景有纵深），
它跟后处理的扫描线打拍子，出来的是摩尔纹而不是速度感——这个坑在骨架的开发过程中
实际踩到过，`fx.zoomBlur` 因此被固定为 0。

## 7. 错位排查表

按这个顺序查，一步一个变量。

| 症状 | 先查 | 处理 |
|---|---|---|
| 翻页总是比鼓点早/晚同一小段 | `config.json -> timing.offset` | 见 `qa-and-delivery.md` 的 offset 语义 |
| 翻页有时对有时不对 | 网格相位错了，不是 offset | 用 `beatgrid.cjs` 的直方图确认相位；或 `tempo_verify.cjs` |
| 元素「一起冒出来」 | 块数多而 `enterBeats` 小 | 提高 `enterBeats`，或减少同页块数 |
| 元素入场拖太久、没落定就被翻走 | `enterBeats` 超过页拍数的一半 | 降到页拍数的 1/3–1/2 |
| 快歌里要点碎成一片 | `bullets.reveal` 为真，二次错开 | 写 `"reveal": false` |
| 全片节奏一样 | 所有页的 `enterBeats` 与页长都相同 | 让副歌页更短更快、主歌页更长更缓 |
| 转场看着在飘 | 用了 push/flip，但音乐是硬切 | 改 `cut` |
| 一页里有两个尖峰，观感乱 | 标了两个 `hit` | 只留一个，另一个改成普通块 |
| 后处理一片死白/死亮 | `flash` 翻页 + 亮色主题 + 高 `glow` | 降主题 `glow`，或换 `cut` |

## 8. 与歌词的关系

`data/lyrics.json` 的每行有 `t` / `dur` / `text` / `key`，应当压在小节线上
（`t = bar * 4 * spb`）。deck 与歌词是两套东西，但要互相咬合：

- **1 行 = 1 页**是最省心也最稳的做法：翻页面 = 歌词行，观众的两条节奏线合一。
- 一行太长（8 拍以上）就拆成两页：前 4 拍给「是什么」，后 4 拍给「为什么」。
- `key` 字段（那行歌里最关键的那个字）就是 `hit` 该标的位置：把它做成 `[[key]]` 强调，
  并让那一块带 `hit: true`。

如果歌词和 deck 打架（页翻得比词快），**改 deck，不要改歌词**：词是内容，
页只是版式。

## 9. MV 型：切点跟着人声走，不是跟着小节走

上面八节讲的是**讲解型**（一页一段话，翻页落小节线）。**MV 型一旦给每一刀都配了字幕
（见 `subtitles.md`），切点就必须换依据**——继续按"每 2 小节"切，字会和人声错开：
字幕先亮起来、人还没唱，或者唱完半句字才换。

镜头表里写 `t`（这一句唱到的秒），由脚本吸到最近的**八分音符**：

```js
const Q = F.grid.periodSec / 2;                                  // 八分音符
const snapped = (t) => Math.max(0, Math.round((t - F.grid.beat0) / Q) * Q);
atBar: +((snapped(sh.t) - B0) / (4 * F.grid.periodSec)).toFixed(4)
```

**为什么是八分音符，不是小节。** 吸到小节会把切点推离那个字最多三分之一秒——
在歌词片里这点抖动最扎眼。完全不吸则丢掉网格，测的 BPM 就白测了。
八分音符（快歌约 0.17s）是这两者之间唯一的平衡点，也是这一类歌本身的驱动单位
（lulu. 有约 65% 的起音落在拍或半拍上）。

**`atBar` 因此会是小数**，这不是错误：它仍然精确落在网格上，只是网格比"小节"细。
`deck_smoke.mjs` 判定"翻页在线上"要用与网格周期取模，**不要**要求它是整数。

### 歌词时间码要跟"你渲染的那一个版本"对齐

| 来源 | 优先级 | 风险 |
|---|---|---|
| 官方 MV / 官方歌词视频字幕 | 最高（有人逐句对过） | **可能对应另一个版本** |
| 正规 LRC（单曲） | 高 | 版本要核对 |
| 自己听打 | 兜底 | 慢，但不会错版本 |

**这个坑实测踩到过：** lulu. 的官方 MV 中文字幕首句在 **11.09s**，而单曲在 **1.0s**
就已经到 −16 dB 了——官方 MV 比单曲整轨晚 **9.59 秒**。对 `features.json` 的 onsets
做 −13…+13s 的 offset 扫描，最优只在一个弱峰（−8.25s），不可信。**官方 MV 字幕直接不可用。**

核对办法（任选一个，都要做）：

1. 看波形：声音真正起音的位置 vs 第一句歌词的时间码。
2. 拿 `features.json` 的 onsets 做 offset 扫描，找**强**峰；弱峰就是没对上。
3. 比时长：两个版本的 duration 是否一致。

### 无词的段落也要切，也要有字

scat 副歌、哼唱、纯器乐尾奏——切点照旧从音乐走（那里通常还有清晰的乐句），
字幕写歌自己的音节，或者把上一句留住。切不出来就**不要硬切**：尾奏横跨 19 秒只留 4 刀，
比切成 12 刀每刀 1.6 秒好。
