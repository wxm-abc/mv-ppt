# 主题：把 PPT 的配色变成 MV 的颜色状态

`ppt-animation` 的配色是一组 CSS 变量（`--paper / --ink / --red`…）。
本技能把它换成一组**有语义的角色**，因为 MV 的颜色必须是**状态**（六条铁律第 3 条）：
一套主题对应故事里的一个段落，由歌词里的事件进入，而不是每页换一个好看的配色。

读这份文档的时机：要新增或改写一套主题、页面看起来太灰/太亮、要判断对比度够不够。

---

## 1. 角色表

`config.json -> palettes` 里每套主题有 13 个颜色角色 + 2 个标量。角色名固定，
`deck.js` 只认这些名字。

| 角色 | 语义 | 用在哪 |
|---|---|---|
| `bg` | 页面底色 | 背景、反白字 |
| `panel` | 更暗的表面 | 背景的暗部、渐变的深端 |
| `raised` | 抬起的表面 | 卡片、对比栏、徽章底 |
| `line` | 发丝线 | 网格线、未填充的进度条、分隔 |
| `text` | 主文字（标题） | title、body、卡片标题 |
| `sub` | 次级文字 | sub、正文、图解说明 |
| `mute` | 三级文字 | 页码、注脚、非重点标签 |
| `me` | **强调色** | kicker、图表条、图标、`[[标记]]` |
| `meHot` | 强调色的亮端 | 高光、渐变亮端 |
| `meDim` | 强调色的暗端 | 渐变暗端、非重点的强调 |
| `err` | 错误红 | `stat` 的负向 delta |
| `errDim` | 错误红的暗端 | 同上，暗部 |
| `bloom` | **光的颜色** | 泛光染色、flash 颜色、背景光池 |
| `glow` | 标量 | 泛光强度倍数（0.3 浅底 ~ 1.5 深底） |
| `sat` | 标量 | 画面保留多少饱和（0 = 灰阶） |

`bloom` 是这套系统里最容易被忽略、也最决定「贵不贵」的一个：**它是灯光的颜色，不是颜色本身**。
深色主题用浅而偏冷/偏暖的 tint，浅色主题必须用同样浅的白，否则泛光会把整页糊掉。

| sat | 1.00 | 1.00 | 1.00 | 0.95 | 0.95 |

对应关系（来自 `ppt-animation` 的五套风格）：

- `dark-tech` ← 黑底 + 蓝/紫渐变（默认、最安全）
- `cyber-red` ← 黑底 + 红橙发光（情绪最冲，适合副歌）
- `gradient-dark` ← 深蓝紫渐变底（比 dark-tech 更冷、更远）
- `warm-paper` ← 米白纸张 + 深色墨迹（回忆、日常、叙事）
- `clean-white` ← 白底 + 深色字 + 彩色点缀（收尾、打开、清晨）

## 3. 从一份 PPT HTML 模板反推一套主题

`assets/ppt-themes/` 里放了五份现成的 PPT 风格 HTML。反推步骤：

1. 打开文件，抄下 `:root` 里的 CSS 变量。
2. 按下表映射到角色。
3. 定 `glow` / `sat`（见 §4）。
4. 在 `deck.json` 里给一页挂上它，跑 `deck_smoke.mjs` 看有没有拼错。

以 `PPT-warm-paper-demo.html` 为例：

```css
:root { --paper:#f4f1ea; --ink:#1a1a1a; --red:#c41e3a; --yellow:#e4a010; --blue:#1e3a5f; --gray:#6b6b6b; }
```

| CSS 变量 | 角色 | 值 |
|---|---|---|
| `--paper` | `bg` | `#f4f1ea`（略降饱和到 `#f2ece0`，避免泛光发黄） |
| `--ink` | `text` | `#1a1a1a` |
| `--gray` | `sub` / `mute` | `#6b6b6b` 提亮/压暗成两级 |
| `--red` | `me` | `#c41e3a`（偏冷，改成 `#c0392b` 更暖） |
| `--yellow` | `meHot` | `#e4a010` 系 |
| `--blue` | `err` 或 `meDim` | 报纸风里蓝是第二强调色，本系统只给一个强调色，所以降级 |
| （纸白） | `bloom` | `#ffd9a8`（纸面反射的暖光） |

**本系统只有一个强调色。** PPT 模板常常有红/黄/蓝三个并列强调色；在一页幻灯片上那是
信息色，在 MV 里会读成花。规则是：挑一个当 `me`，其余降级成 `meHot / meDim` 或
`err`。需要区分两类数据时，用 `me` 与 `err`，不用第三个色相。

### 多套并列色怎么处理

`stat` 的正负、`compare` 的左右，用 `me` 与 `err` 就能表达。真要第三个色相，
把它做成**另一套主题**（颜色是状态），而不是同一页里的第三个强调色。

## 4. 浅色主题的坑（实测）

浅底 + 深字是本系统里最容易出问题的一类。

1. **`glow` 必须降下来。** 泛光只吃饱和像素，但浅底本身很亮，泛光一强整页就发白。
   深色主题用 0.9–1.25，浅色主题用 **0.3–0.6**。
2. **`bloom` 不能用强调色。** 强调色做 bloom，浅底会被染成一块彩。浅色主题的 `bloom`
   取「纸白偏一点色温」（`#ffd9a8` / `#cfe0f7`）。
3. **`line` 不能太浅。** 浅底上的发丝线和网格很容易看不见；`#d3dae4` 是这个尺度上的下限。
4. **`raised` 与 `bg` 要拉开。** 浅色主题里卡片是**更白**的（`#ffffff` on `#fbfcfd`），
   靠 1 级明度差 + 描边立起来，不要靠阴影（canvas 阴影在逐帧渲染里很贵）。
5. **`err` 与 `me` 要拉开色相。** `#d0342c`（红）与 `#2f6fd0`（蓝）没问题；
   如果 `me` 也偏红，`stat` 的涨跌就分不清了。
6. **收尾用浅色是有含义的。** 骨架里 vignette 从 0.62 递减到 0.30，最后一页最开、
   最亮——浅色主题放在最后一页，画面是「打开了」，这是有意义的，不是配色偏好。

## 5. 对比度自检

在 1080p 上，字太小 + 对比不足 = 观众看不清。至少满足：

| 用途 | 对比度下限 |
|---|---|
| `text` on `bg`（标题） | 7:1 |
| `sub` on `bg`（正文） | 4.5:1 |
| `mute` on `bg`（页码/注脚） | 3:1 |

快速自算（相对亮度用 sRGB 近似即可，不必上 WCAG 的精确公式）：

```js
const lum = (hex) => {
  const c = [1, 3, 5].map((i) => parseInt(hex.slice(i, i + 2), 16) / 255)
    .map((v) => (v <= 0.03928 ? v / 12.92 : Math.pow((v + 0.055) / 1.055, 2.4)));
  return 0.2126 * c[0] + 0.7152 * c[1] + 0.0722 * c[2];
};
const ratio = (a, b) => {
  const [x, y] = [lum(a), lum(b)].sort((p, q) => q - p);
  return (x + 0.05) / (y + 0.05);
};
ratio('#eef1ff', '#141726');   // dark-tech 的 text/bg -> 约 13.9
```

拿不准的时候，把主题色贴进任意在线对比度检查器算一次，比凭眼睛可靠。

## 6. 什么时候换主题

**颜色是状态：** 换主题就是故事转段。三条规矩：

1. **同一段落内不换。** 一页一个主题、每页都换，是配色轮播，不是叙事。
2. **换主题必须有一个事件。** 副歌第一拍、鼓进来、段落开始、某个词第一次出现。
   写进 `docs/PLAN.md`：「第一次红在 129.34 s」这种句子。
3. **首尾要成对。** 第一页最收（vignette 最高、颜色最冷），最后一页最开。
   骨架的 `VIG` 数组就是干这个的；改了主题顺序也要改它。

一个可用的最小方案（骨架的示例 deck 用的就是这个）：五页五个主题，
按「冷 → 冲 → 远 → 暖 → 亮」走一遍，正好覆盖五套风格，也正好是五段情绪。
如果一首歌只有一个情绪，**就不要五套主题**——一套主题 + 五个不同版式，
比五套主题更高级。
